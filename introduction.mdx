Query Agent is a data-query-oriented NL2DSL agent. You send it a plain-language question — for example, "Show PV for app_launch in Germany over the last 7 days" — and it extracts the intent, resolves catalog metadata, and returns a structured DSL your downstream query system can execute.

## Why Query Agent

Building a natural language interface for analytics is hard. Query Agent handles the hardest parts:

- **Intent extraction** — parses free-form text into structured fields (`event`, `metric`, `time`, `region`, `group_by`)
- **Catalog matching** — maps natural-language terms to canonical event and dimension names in your metadata catalog
- **Multi-turn conversations** — follow-up questions patch the previous query state instead of starting from scratch
- **Confirmation flow** — when resolution is ambiguous, the agent returns candidates and waits for explicit confirmation
- **Memory layers** — session context, project-level business rules, and per-user preference signals all improve results over time

## How it works

Every query goes through this pipeline:

```
Natural Language
  → LLM Extraction
  → Matcher Resolution
  → QueryState / Turn Logic
  → Semantic DSL
  → Exec DSL
  → Validation
```

The output is a `NL2DSLResponse` containing both a **Semantic DSL** (human-readable normalized intent) and an **Exec DSL** (executable payload for your query backend).
